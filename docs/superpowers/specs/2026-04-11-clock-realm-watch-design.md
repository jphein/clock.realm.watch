# clock.realm.watch Design Spec

## Problem

Claude makes unverified time-of-day claims in conversation. The model has bash access to run `date` but doesn't think to check before making temporal statements. The system injects today's date but not the current time. Rather than admitting uncertainty, Claude confabulates ("it's probably afternoon") from conversational cues.

## Solution

Three-layer temporal grounding system: a behavioral rule, a smart hook, and a fantasy clock UI.

### Layer 1: Global CLAUDE.md Rule

**Location:** `~/.claude/CLAUDE.md` (global, all projects)

**Rule text:**
```
Before any claim about current time, time of day, elapsed time, time zones, or day of week, run `date +"%A %Y-%m-%d %H:%M:%S %Z"` first. Never estimate or infer the time from conversational cues.
```

**Cost:** ~25 tokens, loaded once per session.

**Coverage:** Catches Claude spontaneously volunteering time claims. Weakest layer — Claude can ignore instructions under context pressure, but covers the majority of casual cases.

### Layer 2: Smart UserPromptSubmit Hook

**Location:** `~/.claude/settings.local.json` (raw hook, not hookify — hookify can't execute commands dynamically)

**Event:** `UserPromptSubmit`

**Implementation:** A raw Claude Code hook with `"type": "command"` that:
1. Reads the user's prompt from stdin (`$CLAUDE_USER_PROMPT`)
2. Checks if it matches time-related keywords
3. If matched, runs `date` and outputs a JSON response with `systemMessage` containing the real time
4. If not matched, outputs empty JSON (no-op, zero token cost)

**Hook script:** `~/.claude/hooks/time-awareness.sh`

```bash
#!/usr/bin/env bash
# Read user prompt from stdin
INPUT=$(cat)
PROMPT=$(echo "$INPUT" | python3 -c "import sys,json; print(json.load(sys.stdin).get('userPrompt',''))" 2>/dev/null)

# Check for time-related keywords (case-insensitive)
if echo "$PROMPT" | grep -qiE '(what time|how long ago|when did|how recent|minutes ago|hours ago|elapsed|schedule|deadline|eta|this morning|this evening|tonight|yesterday|tomorrow|how late|time is it|time ?zone|how early|since when|time remaining|time left)'; then
  TIME=$(date +"%A %Y-%m-%d %H:%M:%S %Z")
  echo "{\"systemMessage\": \"Current system time: $TIME — use this value, do not estimate or guess.\"}"
fi
```

**Hook entry in settings.local.json:**
```json
{
  "hooks": {
    "UserPromptSubmit": [
      {
        "matcher": "",
        "hooks": [
          {
            "type": "command",
            "command": "bash ~/.claude/hooks/time-awareness.sh",
            "timeout": 2000
          }
        ]
      }
    ]
  }
}
```

**Cost:** ~25 tokens when fired (the systemMessage), zero tokens when not fired. Fires only on time-related prompts (~5% of messages).

**Coverage:** Catches direct time questions and gives Claude the real answer before it can hallucinate one. Strongest layer for user-initiated time queries.

### Layer 3: Static Fantasy Clock UI

**Location:** `/home/jp/Projects/clock.realm.watch/index.html`

**Tech:** Single HTML file, inline CSS + JS. No build step, no server, no dependencies.

**Features:**
- Live clock face updated every second via `new Date()`
- Fantasy aesthetic: Cinzel headings, Inter body, grimoire surface, gold rim borders, gem accent colors
- Dark/light theme via `prefers-color-scheme` CSS custom properties
- SVG favicon (clock/astrolabe motif)
- Responsive layout

**Realm:** `stellar` (astronomical — fits a clock's domain)

**Versioning:** `version.json` generated by `~/Projects/realm-sigil/static/build.sh`:
```bash
~/Projects/realm-sigil/static/build.sh \
  --name clock.realm.watch \
  --description "Temporal grounding for the realm" \
  --realm stellar \
  --repo https://github.com/jphein/clock.realm.watch \
  --html index.html
```

## What This Does NOT Do

- Does not add an MCP tool (no server to maintain). If Claude needs the time, it runs `date` in bash.
- Does not fire on every message. The hook is targeted to time-related prompts only.
- Does not block any operations. Both layers are advisory — `warn` action, not `block`.
- Does not require a running server. The clock UI is static HTML opened with `xdg-open` or served via any static file server.

## Future Expansion

If the CLAUDE.md rule + smart hook prove insufficient:
- Escalate to a `pattern: .*` hook that injects time on every message (higher token cost, guaranteed coverage)
- Add an MCP tool (`get_time`) so Claude has a native tool instead of shelling out to `date`
- Add a Go/Python server if the clock needs an API beyond static version.json
